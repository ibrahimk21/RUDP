# Benchmarking methodology

This file governs TASKS.md Phases 8-10. Deterministic correctness belongs to TASKS.md. Configuration errors invalidate experiments; poor transport performance, failure, and disagreement with a hypothesis do not. Freeze a machine-readable configuration implementing these rules before final collection. Pilots are labeled and excluded from final inference.

## Network and baseline contract

Use four disposable Linux network namespaces joined by veth links: sender -- shaper -- delay -- receiver. Forward packets are rate-limited at the shaper and delayed/dropped downstream at the delay namespace; reverse packets are rate-limited at delay and delayed/dropped downstream at shaper. Thus impairment is outside the sending endpoint's socket stack, toward receiver ingress. Do not benchmark using a root netem on host loopback. [The iproute2 netem manual](https://kernel.googlesource.com/pub/scm/network/iproute2/iproute2-next/+/refs/heads/main/man/man8/tc-netem.8) explains TCP Small Queues placement effects and netem limitations.

Use HTB for each directional bottleneck (rate=ceil), with a byte FIFO leaf sized for 50 ms of serialization at that rate. Use separate downstream netem queues for propagation/loss, limit 65536 packets, so the propagation buffer is not confused with the bottleneck queue. Primary capacity is 20 Mbit/s in each direction; FIFO size =125000 bytes. Record actual HTB burst/cburst/quantum settings and calibration; start with burst=cburst=16 KiB and quantum=1514 bytes. Rate accounting is that of the Linux qdisc, not a claim of physical satellite framing.

Set veth MTU=1500. Disable TSO/GSO/GRO and other segmentation/coalescing offloads wherever supported on every test interface; verify packet sizes in captures, not only ethtool output. TCP uses the resulting natural MSS; do not force it to RUDP's 1024-byte payload. Report that packet size affects per-packet loss exposure. Add a GEO-2% sensitivity run with TCP_MAXSEG=1024 on both TCP baselines before connect, verify negotiated MSS, and label it separately from the primary baseline.

Use unchanged TCP congestion algorithms, explicit per-socket selection with readback. Keep TCP autotuning enabled with namespace-local send/receive maxima at least 16 MiB; record all changed sysctls and observed buffer/window sizes, including kernel doubling conventions. Both RUDP endpoints request 16 MiB UDP socket buffers and verify effective sizes. RUDP protocol buffers remain the TASKS.md 8192-slot limit. These are disclosed environment settings, so label results TCP-CUBIC/TCP-BBR rather than universally 'unmodified default TCP'. Record the exact BBR implementation/kernel and endpoint pacing qdisc; use fq at endpoints if available and verify TCP pacing rates. Do not silently change pacing between protocols.

At 20 Mbit/s and 600 ms, payload BDP is approximately 1.5 MB, below the 8 MiB RUDP payload window. Verify receiver credit, socket drops and actual flight size under load; field width alone is not evidence of BDP support. If tuning is necessary to remove a host bottleneck, apply it before final collection, record it, and restart affected comparisons.

### Primary profiles

All listed loss models apply independently in each direction, with distinct recorded seeds. Delay is fixed in primary profiles to isolate loss behavior; jitter is a separate sensitivity, not a hidden default.

| Profile | One-way delay each direction | Loss per direction | Rate |
|---|---:|---|---:|
| Terrestrial | 5 ms | none | 20 Mbit/s |
| GEO | 300 ms | independent random 2% | 20 Mbit/s |
| Synthetic LEO | 20 ms | `gemodel 1% 20% 100% 0%` | 20 Mbit/s |

LEO's Gilbert-Elliott model uses good-to-bad probability 0.01, bad-to-good probability 0.20, loss in bad=1 and good=0: stationary loss approximately 4.76%, mean bad-state run five packets. This is a stylized packet-indexed burst model, not a Starlink trace or time-based handover model. Validate realized distributions and state interpretation on the installed netem version.

Mandatory sensitivities: GEO random loss {0,1,2,3}% at fixed 600-ms RTT/rate; the primary 2% cell is reused, not counted twice. Add GEO with uniform one-way jitter +/-20 ms and LEO with +/-5 ms; keep their loss models unchanged, explicitly allowing resulting reordering. Matched-MSS sensitivity is specified above. Do not infer a loss-scaling law by comparing terrestrial and GEO, or fit an inverse-square-root law at p=0.

### Preflight and cleanup

A script creates only namespaced resources with a unique run prefix and installs cleanup traps for normal exit, signals and errors. Keep a manifest of owned resources for recovery after an uncatchable crash. Never delete unrelated namespaces/interfaces or alter host network defaults. Launch measurement applications unprivileged after topology setup; privileges are for network configuration and capture only.

Before experiments, validate each profile using at least 100 unloaded RTT probes and a 10000-packet low-rate sequence probe per direction. Check mean added RTT within max(5 ms,5%) of target and independent-loss rate within max(0.5 percentage points,3 binomial standard errors) of target. For LEO use ten independent probe seeds; require mean loss within 1 percentage point and mean loss-run length within 20% of target, recording the complete run-length distribution. Failed calibration triggers investigation, not parameter adjustment chosen to favor RUDP.

Use a paced saturation probe for 30 seconds after 5 seconds settling: delivered rate should be within 10% of the expected qdisc-limited rate after accounted headers/loss. Check packet-size distribution, no endpoint socket drops, propagation queue occupancy far below its cap, and identify bottleneck queue drops separately from intentional loss. Save qdisc/class counters and queue samples before/during/after each run. TCP's algorithm readback and offload verification are required gates. In an overloaded transport run, queue drops are a result: retain it and do not call its loss exclusively non-congestive.

## Workloads and metrics

All namespaces share one kernel monotonic clock; processes use CLOCK_MONOTONIC without time namespaces. Use identical application record format/body generation for reliable protocols: 1024-byte records containing big-endian uint64 record ID and uint64 offer timestamp in nanoseconds plus deterministic body bytes. Timestamps vary by run and remain unchanged on retransmission. Handle TCP stream splitting/coalescing explicitly. RUDP maps each full record to DATA. Validate IDs/body independently of digests. Timestamps and record envelopes count toward application bytes for every protocol; transport/control/retransmitted bytes do not count as delivered goodput.

1. **Primary sustained stream:** new connection per run; source starts after setup, generates records as fast as bounded API/backpressure permits for 120 seconds, then drains and closes with final length/digest. Measure receiver-delivered unique bytes in [t0+30 s,t0+120 s), divided by exactly 90 seconds; t0 is sender's first record offer. First 30 seconds are a declared settling interval, not proof of steady state: retain per-second series to show continued growth/drift. Deadline for drain/close is 120 additional seconds. Enforce transfer/resource caps from TASKS.md. Include setup, drain and failures as separate outcomes.
2. **File completion:** fixed deterministic files of 1 KiB and 1 MiB, same bytes and pre-read cache policy. Prehash/warm file pages before timing; time from sender setup initiation until verified completion confirmation. Goodput is verified file bytes / that duration. Disk writes and output commit are included; no fsync durability claim. Deadline=1800 seconds. Raw UDP has no reliable file-completion result.
3. **Application latency:** separate 120-second stream offering one record every 20 ms after setup; timestamp immediately before attempting API acceptance, so sender backpressure and receiver head-of-line waiting are included. One outstanding offer at the application boundary; after blocking, resume scheduling without a catch-up burst. Report achieved offer/delivery rate and blocked time. Latency = ordered receiver application-delivery time minus offer time; percentiles exclude undelivered records but report their count/fraction and deadline censoring. No pooling of TCP wire segments with RUDP packets.
4. **Setup and first byte:** use file runs to record setup initiation -> sender transport-ready, and setup initiation -> first application byte received, separately. RUDP OPEN_ACK and TCP connect completion define readiness; identical application metadata exchange follows for TCP. Empty files have no first-byte value. Neither side uses TLS; no security-equivalent handshake advantage is claimed.
5. **Controlled loss recovery:** separate backlogged finite stream of 8193 records at each profile's fixed delay/rate with background random loss disabled (record IDs start at zero). Arm before DATA starts; drop exactly the first transmission of the packet containing record 4096's first byte at the downstream impairment point. A reusable one-shot packet filter/capture helper identifies TCP stream offsets after segmentation and RUDP record IDs. Record injection timestamp/offset, prove exactly one drop, and identify any other records affected by the same TCP segment. Recovery is injection -> ordered delivery of the target record; also report retransmission mechanism/counters, later-data evidence and flight size. Add a 4097-record trial dropping its final record instead; SACK recovery is not required there. Both have 1800-second deadlines. Helper implementation/validation is part of Phase 8; never replace this with comparing RTO settings. Preflight its compiler/kernel/capture dependencies in Phase 0; freeze its implementation and verify retransmissions bypass the one-shot drop.

Raw UDP uses the sustained generator paced at a 20-Mbit/s budget including observed IP/UDP/record headers, two-datagram burst cap. Receiver counts unique validated bytes and duplicates/loss; harness control channel outside the impaired path establishes timestamps and bounded stop. Report delivered goodput, offered/wire rate, delivery fraction and unordered latency separately; ordered latency, setup, recovery and file success are N/A. It cannot serve as a reliability-equivalent baseline.

CPU: capture user+system CPU seconds for both endpoint processes over the same sustained measurement interval; report their sum per delivered MiB and individually. Exclude setup/drain from this metric. Report host/shaper CPU separately where available and acknowledge interrupt/softirq attribution limitations. Use lightweight counters in primary runs; evaluate full tracing overhead in paired pilot runs, and keep heavy packet capture for validation/recovery trials unless its goodput effect is <=2% for every compared protocol.

For every sustained run also record retransmitted DATA/bytes, total IP bytes both directions at a declared capture point, duplicates, checksum rejects, socket/queue drops, cwnd, credit/flight samples and RTO counts. Overhead = total bidirectional IP bytes / unique delivered application bytes; zero delivery produces N/A, not division by zero. Buffer diagnostic logs in bounded memory and flush outside timed intervals; record lost log samples.

## Coexistence and congestion response

Use two backlogged sustained flows sharing the same forward bottleneck, with independent ports and receivers. Test RUDP-AIMD or Sat with CUBIC and separately BBR, plus CUBIC+CUBIC and BBR+BBR controls. Run each primary profile and a GEO-delay congestion-only profile with no injected loss. Repeat with a capacity step 20 -> 5 Mbit/s at t=60 seconds in the congestion-only case; resize the bottleneck FIFO to retain the 50-ms queue budget. Restore it between runs.

Start both flows behind a harness barrier; alternate endpoint/launch roles across repetitions. Duration=120 seconds. Report per-flow goodput and Jain's index `(x1+x2)^2 / (2*(x1^2+x2^2))` over common windows [30,60) and [90,120), plus per-second share, queue delay/occupancy, drops, utilization, and settling after the capacity step. For fixed-capacity runs also report [30,120). Index is N/A when both deliver zero. Report TCP's share and absolute goodput as well as the index: equal starvation is not good performance. Do not use two independent shapers masquerading as a shared bottleneck.

## Sampling, ordering and inference

A cell is experiment kind x profile/sensitivity x protocol/CC (or coexistence pair) x workload parameters. Reliable protocols use every primary workload; raw UDP uses only the primary sustained workload and its unordered record latency, not the separate reliable latency workload. Sensitivities use sustained reliable streams only. Controlled loss uses fixed-delay/no-background-loss derivatives, as defined above. Application-latency trials have the sustained trial's 120-second drain/close allowance. Each cell has one labeled warm-up plus ten retained runs. Warm-up exclusion never removes slow start from later new connections; within-run settling is specified separately.

Generate and store the complete schedule and PRNG seeds before measurement. Use randomized balanced blocks: randomize profile order per block and rotate/shuffle protocol order so each occupies early/late positions equally where possible. Every compared variant runs in the same block/session. Independent directional impairment seeds are fixed by block/profile and reused across variants for comparable distributions, not claims of identical loss events (packetization/schedules differ). Preserve scheduler/generator/netem seeds and actual commands. Use distinct pilot and final seeds.

Close unnecessary host workloads; record Windows/WSL/kernel versions, CPU/memory/power mode, affinity policy and host load. Do not change affinity/power policy mid-session. Run three fixed terrestrial CUBIC controls at each session boundary. If median goodput differs by >10% or unloaded median RTT differs by >max(2 ms,10%), retain/label the entire session suspect, investigate, and rerun the affected complete blocks; never keep only favorable protocols. Stop before a new block if controls/resources fail.

Retain all attempted runs. Exclusion requires objective harness/configuration failure (wrong algorithm, broken shaper, corrupt logging, unrelated process crash), a recorded reason, and replacement of the whole affected comparison block. Transport timeouts, integrity failures and high latency are results, not outliers. No 2-SD trimming or deletion based on host-load impressions. An integrity failure additionally blocks correctness completion and requires a new revision/repetition of affected experiments after repair.

Report per-cell n, failures, mean and sample SD for sustained goodput. A transport failing before the measurement interval ends contributes zero primary sustained goodput; retain partial delivery separately. Successful transfer goodput is conditional on completion and must appear beside timeout/failure counts, never treating unfinished files as completed. Show both all-run and success-only sustained summaries where failures occur.

Report median of run-level p50/p95/p99 latency, their spread, sample counts and undelivered fraction; do not treat individual records as independent experimental repetitions. For headline ratios use ratio of cell mean sustained goodputs, with 95% percentile bootstrap intervals from 10000 resamples of whole matched blocks (record bootstrap seed). Resample runs, not packets. Zero baseline mean makes a ratio undefined. Apply the same block bootstrap to relevant target comparisons and label exploratory sensitivities; do not claim correction for unlimited multiple testing.

Stop after the ten predeclared retained blocks; no outcome-dependent repetition extensions. Wide intervals or undefined ratios remain inconclusive. A follow-up study needs a separately frozen sample size/configuration and independently reported data, not repeated sampling until a win. Targets are met only if the lower CI bound reaches the PLAN.md threshold (strictly >1 for the CUBIC win); these are per-comparison intervals, not a joint confidence guarantee across all targets. Sample count is not a guarantee of statistical power. Fixed-MSS and jitter results do not replace primary results.

## Artifacts and threats to validity

Use immutable `results/<experiment-id>/` directories. Commit `manifest.json`, `schedule.csv`, `runs.csv`, `records.csv` (or losslessly compressed equivalent), `events.csv`, queue/time-series data and graphs. Manifests include repository revision/dirty patch, compiler/flags, Python/tool versions, machine/kernel/BBR identity, complete topology/qdisc/sysctl/offload/buffer/MTU state, workload bytes/digests, deadlines, seeds, clock/pacing configuration, schema version and exact reproduction commands.

Each run row references manifest/block/session IDs, workload/profile/variant/seed, warm-up/exclusion flags and reason, status/error, timing boundaries, offered/delivered/wire/retransmitted bytes, duration, goodput, percentile/sample counts, setup/first-byte/recovery values as applicable, CPU times, digest status, and sample-file paths. Coexistence rows reference both flow IDs and shared windows. N/A is explicit. Preserve pre/post configuration and counters; plots are regenerated only from these artifacts with recorded filters and calculations.

The report must explain: single-machine/WSL scheduling and shared CPU effects; residual kernel/offload/pacing/packet-size differences; synthetic independent/burst loss rather than measured satellite traces; possible queue loss alongside injected loss; finite samples and exploratory comparisons; throughput/latency/security feature differences from TCP/QUIC; unauthenticated laboratory-only transport; Sat's inability to identify physical loss causes; instrumentation bias; and absence of external validation unless such validation actually occurred. Absolute results describe this setup; even relative results require these qualifications. Report negative results and unmet targets plainly.
